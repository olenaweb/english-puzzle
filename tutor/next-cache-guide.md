# Папка `.next` в Next.js - Полное руководство

## Что это такое?

`.next` — это служебная папка, которую автоматически создает Next.js при запуске проекта. Она содержит:

- **Скомпилированный код** вашего приложения
- **Кеш сборки** для ускорения повторных запусков
- **Оптимизированные файлы** для production
- **Сгенерированные типы TypeScript** (например, `routes.d.ts`)
- **Метаданные страниц и маршрутов**

## Структура папки `.next`

```
.next/
├── cache/              # Кеш для оптимизации сборки
├── server/             # Серверный код (Server Components)
├── static/             # Статические файлы и чанки
├── types/              # Автогенерируемые типы TypeScript
├── dev/                # Файлы для development режима
│   └── types/          # Типы для разработки
└── trace               # Данные для трассировки и отладки
```

## Для чего нужна?

### 1. **Ускорение разработки**
- Кеширует результаты компиляции
- Не перекомпилирует неизменившиеся файлы
- Сокращает время hot reload

### 2. **Оптимизация production сборки**
- Минификация и бандлинг кода
- Tree-shaking (удаление неиспользуемого кода)
- Code splitting (разделение на чанки)

### 3. **Генерация типов**
- Автоматически создает типы для маршрутов
- Типы для API routes
- Типы для динамических импортов

### 4. **Turbopack кеш** (Next.js 13+)
- Хранит промежуточные результаты компиляции Rust-based Turbopack
- База данных SST файлов для инкрементальной компиляции

## Когда нужно очищать кеш?

### ✅ Обязательные случаи:

1. **Странные ошибки компиляции**
   ```
   Error: Module not found
   Cannot find module './component'
   ```

2. **Изменения не применяются**
   - Код изменился, но на странице старая версия
   - Hot reload не работает

3. **Ошибки TypeScript с путями**
   ```
   Cannot find name 'routes'
   Module augmentation error
   ```

4. **Ошибки Turbopack** (в Next.js 16+)
   ```
   Failed to lookup task type
   Unable to open static sorted file
   ```

5. **После обновления Next.js**
   - Новая версия может изменить структуру кеша

6. **Проблемы с environment variables**
   - `.env` файлы не подхватываются

7. **После изменения конфигурации**
   - Изменили `next.config.ts`
   - Изменили `tsconfig.json`
   - Добавили новые middleware/proxy

### ⚠️ Рекомендуемые случаи:

- Перед деплоем на production
- После смены ветки git с большими изменениями
- При конфликтах после git merge
- Если dev-сервер ведет себя странно

## Как очистить кеш?

### Способ 1: Вручную удалить папку

**PowerShell (Windows):**
```powershell
Remove-Item -Recurse -Force .next
```

**Terminal (macOS/Linux):**
```bash
rm -rf .next
```

### Способ 2: Через npm скрипт

Добавьте в `package.json`:
```json
{
  "scripts": {
    "clean": "rm -rf .next",
    "dev:clean": "npm run clean && npm run dev"
  }
}
```

Затем:
```bash
npm run clean
npm run dev
```

### Способ 3: С остановкой процессов (Windows)

Если файлы заблокированы:
```powershell
# Останавливаем все процессы Node.js
taskkill /F /IM node.exe

# Ждем 2-3 секунды
Start-Sleep -Seconds 3

# Удаляем кеш
Remove-Item -Recurse -Force .next

# Запускаем заново
npm run dev
```

### Способ 4: Полная очистка (включая node_modules)

Если проблема серьезная:
```bash
# Удаляем все
rm -rf .next node_modules package-lock.json

# Переустанавливаем зависимости
npm install

# Запускаем
npm run dev
```

## Что происходит после очистки?

1. **При следующем запуске** `npm run dev`:
   - Next.js создаст папку `.next` заново
   - Произойдет полная компиляция (займет больше времени)
   - Сгенерируются все типы и маршруты

2. **Временно могут появиться ошибки TypeScript**:
   - Это нормально - типы еще не сгенерированы
   - Исчезнут после завершения первой компиляции

3. **Dev-сервер запустится дольше**:
   - Первый запуск без кеша всегда медленнее
   - Последующие запуски будут быстрыми

## Нужно ли добавлять `.next` в `.gitignore`?

**✅ ДА!** Эта папка всегда должна быть в `.gitignore`:

```gitignore
# Next.js
.next/
out/
build/

# Next.js cache
.next/cache/
```

### Почему?

- **Генерируется автоматически** - не нужно хранить в репозитории
- **Зависит от окружения** - у каждого разработчика своя версия
- **Большой размер** - замедлит работу с git
- **Может содержать sensitive data** - environment variables

## Production сборка

Для production используется команда:
```bash
npm run build
```

Это создает оптимизированную версию в `.next`, которая:
- Минифицирована
- Оптимизирована для производительности
- Содержит только необходимый код

После билда запускается сервер:
```bash
npm start
```

## Дополнительные команды очистки

### Next.js встроенная команда (экспериментальная):
```bash
npx next clean
```

Эта команда:
- Удаляет `.next` папку
- Очищает SWC кеш
- Безопасно работает на всех платформах

## Лучшие практики

1. **Не коммитьте `.next` в git**
   - Всегда в `.gitignore`

2. **Очищайте кеш регулярно**
   - Раз в неделю при активной разработке
   - После каждого обновления Next.js

3. **Автоматизируйте очистку**
   - Создайте npm скрипты
   - Используйте в CI/CD пайплайнах

4. **При проблемах - сначала очистите кеш**
   - Это решает 80% странных ошибок
   - Быстрее, чем искать причину

5. **В CI/CD всегда чистая сборка**
   ```yaml
   # GitHub Actions пример
   - name: Build
     run: |
       rm -rf .next
       npm run build
   ```

## Troubleshooting

### Проблема: "Не удается удалить .next - файл занят"

**Решение:**
```powershell
# Windows
taskkill /F /IM node.exe
Start-Sleep -Seconds 2
Remove-Item -Recurse -Force .next

# macOS/Linux
killall node
sleep 2
rm -rf .next
```

### Проблема: "После очистки приложение не запускается"

**Решение:**
```bash
# 1. Полная очистка
rm -rf .next node_modules

# 2. Проверьте package.json на ошибки
npm install

# 3. Запустите
npm run dev
```

### Проблема: "TypeScript ошибки после очистки"

**Решение:**
- Подождите 30-60 секунд после запуска
- Перезагрузите VS Code (Cmd/Ctrl + Shift + P → "Reload Window")
- Перезапустите TypeScript Server (Cmd/Ctrl + Shift + P → "Restart TS Server")

## Заключение

Папка `.next` - это временное хранилище, которое:
- Ускоряет разработку через кеширование
- Автоматически создается и управляется Next.js
- Безопасно удаляется при возникновении проблем
- Не должна храниться в git

**Золотое правило:** При любых странностях - очистите `.next` и перезапустите dev-сервер! 🚀
